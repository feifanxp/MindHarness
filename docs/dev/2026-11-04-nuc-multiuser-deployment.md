## 采用的部署边界

### 一个公开用户入口，一套用户身份

用户入口提供定制聊天客户端和经过枚举的讨论 API。
Matrix 客户端与讨论服务使用同一个已验证账号；浏览器的 Matrix 长期访问令牌不作为管理凭据。
Cloudflare Tunnel 负责把流量送入 NUC；应用仍需独立验证身份、资源所有权和操作权限。
Cloudflare Access 如用于管理入口，应与普通用户的应用登录分开配置，避免 Matrix discovery、登录或认证回调被意外拦截。

### 管理权限独立

配置、凭据、模型供应商、预算管理、执行与电脑控制接口不因持有讨论会话而开放。
管理入口仅允许明确授权的维护身份访问，可复用 Tailscale 或单独的 Access 保护入口。
公网代理默认拒绝未列入用户功能所需清单的后端 API；直接访问源站同样必须通过后端鉴权。
当前讨论流程没有电脑控制需求，不将 computers 代理默认纳入本次公开入口。

### 邀请控制注册，不把邀请码当成管理员密码

第一阶段复用现有 Matrix 注册令牌能力，由运营者分发并保管。
如果产品承诺每人一个邀请码、单次使用、到期或单独撤销，必须先验证当前 homeserver 支持范围，再决定复用其接口或增加最小的邀请管理能力。
撤销注册资格、停用已注册账号和撤销现有应用会话是不同操作，验收时必须分别覆盖。
邀请码、Bot 注册凭据、运营者管理密钥与 Tunnel token 分开管理，不进入浏览器构建、仓库或日志。

### 单机有限容量

保留一个 MindRoom runtime，持久化现有数据并通过现有配置写入机制协调变更。
多人使用不等于把同一存储挂到多个 runtime；仓库已有单实例及 journal 所有权约束。
第一阶段以讨论功能为范围，不默认开放执行工具。
模型推理沿用可用的外部模型服务；本阶段不在这台 NUC 上增加本地大模型推理负载。
给需求澄清调用、房间创建和活跃 Agent 建立可配置的全局及用户级容量控制，并提供明确的排队或拒绝反馈。
具体并发数、活跃讨论数与预算金额在目标用户规模和压测结果明确前不承诺。

### 费用和资源归属

需求澄清、队友生成、聊天室回复与后台整理都应归属到触发或拥有该讨论的用户。
优先复用现有 usage 和 budgets 能力，验证新讨论入口与后台整理是否真正进入同一计量路径。
现有预算文档明确描述超额后切换模型，fallback 仍可继续计费，因此不能对外承诺其等同硬停止消费。
如果上线需要硬上限，应单独实现并验收准入控制，同时覆盖并发请求和已经开始的调用。

## 上线前实施顺序

| 阶段 | 工作 | 放行条件 |
| --- | --- | --- |
| 1：盘点可恢复状态 | 记录实际 Tunnel 的 hostname 到 service 映射、有效配置、镜像版本、卷和外部模型依赖；备份配置与状态 | 备份清单完整，能够在隔离目录验证恢复；不混入开发测试账号和数据 |
| 2：收敛生产入口 | 形成可重复构建的前后端发布产物和 NUC Compose 配置；明确公网 API 白名单、管理入口、HTTPS Origin 与 Cookie | 公网、LAN 和 Tailscale 各入口的身份与授权结果符合预期；从隧道到源站的 Cookie 和转发头行为经真实浏览器验证 |
| 3：账号与邀请闭环 | 验证目标 homeserver 注册流程、统一登录、历史归属、退出、账号停用和邀请码生命周期 | 邀请用户可以完整完成注册到进房；无资格用户不能注册；普通账号不能访问他人的草稿、成果或管理接口 |
| 4：多人容量与计量 | 为讨论创建和推理准入接入用户归属、全局并发与用户配额；验证现有预算覆盖 | 同时创建多个讨论不丢配置、不串数据；超过容量时有可理解反馈，且后台整理不会绕过约束 |
| 5：预发布与升级 | 使用独立预发布卷跑真实端到端和重启恢复；以固定镜像版本升级现有 NUC 服务 | 通过验收矩阵，明确升级窗口，保留旧镜像和配套备份，具备可执行回退路径 |

第 2 阶段与第 3 阶段可以分别准备，但公开用户试用必须等待前四阶段的相关放行条件全部满足。

## 验收矩阵

- A、B 两个真实邀请账号分别创建讨论；A 无法读取或修改 B 的草稿、笔记和房间，除非后续明确实现并授权分享。
- 匿名用户无法创建讨论或调用模型；无邀请码、错误邀请码与已撤销邀请码不能获得新的注册资格。
- 普通用户访问配置、凭据、电脑控制和运营者管理 API 被拒绝，包括通过不同网络入口或直接访问后端端口。
- 隐身窗口、移动端、实际构建路由和公网 HTTPS 下，登录、注册、返回草稿、Token 更新与退出均可完成。
- 浏览器中的 homeserver 公网地址与容器内部地址不相同时仍能验证正确身份并进入房间。
- 多用户同时创建、重命名、归档和删除不同讨论，不覆盖他人的配置或错误停用其他人的 Bot。
- 单用户连续提交和多账号并发提交均受预定容量控制；断开浏览器后后台任务的成本仍可追踪。
- 容器重启后保留讨论与 Matrix 历史；不重复创建房间或重复回复；应用会话需要续签时能够正常恢复。
- 备份包括 Matrix 数据、MindRoom 全部持久状态、配置和必要密钥；在隔离环境演练恢复后再宣布备份可用。
- 从 Tunnel 入口验证实际可用性，解释盘点中的 403 来源；不能以本机健康检查代替公网验收。
